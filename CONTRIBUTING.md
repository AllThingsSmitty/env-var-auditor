## Getting Started

This project uses [pnpm](https://pnpm.io/). Node 18+ is required.

```bash
pnpm install
pnpm build             # compile TypeScript
pnpm test              # unit tests (vitest)
pnpm test:watch        # watch mode for development
pnpm typecheck         # type check without compilation
pnpm lint              # run ESLint
```

The project structure is straightforward:

- `src/` — CLI tool and core analysis logic
- `tests/` — test suite using vitest
- `dist/` — compiled JavaScript (generated by build)

## Ways to Contribute

### Bug Fixes

Search open and closed issues before submitting a bug report or fix to avoid duplicates. Include:

- Minimal reproduction steps
- Expected vs. actual behavior
- Your Node version and OS

### Detection Rules

Add new rules to detect environment variable issues in `src/`. When adding or updating detection logic:

- Explain the security or correctness concern being addressed.
- Add corresponding tests in `tests/`.
- Update the detection approach section in the README if the behavior is user-visible.
- Consider both single-project and monorepo (`--workspaces`) scenarios.

### Output Formats

New output formats (e.g., additional CI/CD platforms) should live in `src/`. When adding a format:

- Implement the formatter interface.
- Add tests covering the output structure.
- Document the format and its use case in the README.

### Configuration

Improvements to `.env-auditorrc.json` schema or CLI flags should:

- Be backward-compatible (new fields must be optional).
- Include validation and helpful error messages.
- Have corresponding tests in `tests/config.test.ts` (or similar).
- Be documented in the Configuration section of the README.

### Documentation

Updates to the README, examples, or pre-commit hook configuration are welcome:

- Keep examples practical and complete.
- Ensure all code samples are tested or verified working.
- Include CI/CD platform examples if relevant.

## Pull Request Guidelines

- Search open and closed PRs to avoid duplicate submissions.
- Keep changes focused — one feature or fix per PR.
- Run `pnpm build`, `pnpm test`, `pnpm lint`, and `pnpm typecheck` before submitting.
- The PR title should be clear and descriptive (see example: "Add detection for hardcoded secrets in code" or "Fix false positive on `NEXT_PUBLIC_` detection").
- Check your spelling and grammar.
- Make sure your editor is configured to remove trailing whitespace.

## Updating Your Pull Request

Sometimes a maintainer will ask you to update your pull request before it can be merged. This is usually due to missing tests, lint errors, scope creep, or because the contribution does not follow the guidelines above.

If you're asked to make changes, simply update your branch and push the new commits to the same pull request.

Thank you for your contribution!
